# 多人共用与并发说明

当前版本适合**可信团队共用一套工作台**。多人可同时打开网站，不同项目也会各自启动后台任务；尚未实现用户作品隔离、全站作业队列或每用户配额。不建议直接作为面向陌生用户的自助生成平台。

## 已核查的行为

| 项目 | 当前行为 |
| --- | --- |
| 多人访问 | Web 使用线程处理 HTTP 请求，多个浏览器可同时访问。 |
| 多个项目生成 | 每次提交会建立独立 job 和后台线程，不同项目可并发启动。 |
| 同项目写入 | 生成管线对项目目录加文件锁；同一项目不可同时生成/修改。重复提交可能先得到 job，再由后台报告项目忙。 |
| 用户权限 | 宝塔 Basic Auth 是入口登录，不会建立应用中的作品所有者权限。 |
| 任务访问 | 已登录者拿到其他任务 ID 后，可查看其进度或请求停止；文件/项目也没有用户所有权校验。 |
| 任务日志 | 已复现并发任务日志混入其他项目的情况，生成提示词等日志可能跨项目显示。 |
| 全站并发 | 没有活跃作业数硬上限或持久化排队；重复提交会继续创建线程。 |
| 图片并发 | `INKSTONE_IMAGE_CONCURRENCY` 限制单次生成管线中的图片并发，并非全站活跃任务数。 |
| 接口限频 | 有进程内共享的请求限频桶，但它不等于用户配额或生成任务队列，也不跨进程共享。 |
| 重启恢复 | job 保存在内存；项目文件保存在磁盘。重启后需用原项目编号重新提交以尝试续跑。 |

## 团队现在怎么用

1. 按 `README.md` 部署一个进程，由宝塔 Nginx 反代；不要在 Python 项目管理器或 Gunicorn 中再开多个 worker。
2. 只分配给相互信任的运营人员。账号可分开管理，但所有人仍在共用同一工作空间。
3. 每个人使用不同项目编号，例如 `alice-book01-ch01`、`bob-book02-ch01`；同一篇续跑沿用原编号，改变正文/画风时新建编号。
4. 起步先设 `INKSTONE_IMAGE_CONCURRENCY=1`，团队约定同一时刻只由一人提交生成，其他人可浏览和预览。**这条约定不会被当前系统自动强制执行。**
5. 等当前任务完成后再安排下一篇。先用短内容测量内存、图片吞吐、429 频率和调用成本，再决定是否需要开发队列或扩容。

添加运营账号（第一次部署已有密码文件后，**不要加 `-c`**，否则会覆盖原账号）：

```bash
htpasswd /etc/sorvflow/htpasswd alice
htpasswd /etc/sorvflow/htpasswd bob
chown root:www /etc/sorvflow/htpasswd
chmod 640 /etc/sorvflow/htpasswd
```

`www` 为宝塔默认 worker 组；若已改动，使用实际 Nginx worker 可读的组。每人用自己的浏览器配置文件；同一浏览器同域名多标签页会共用本地任务恢复记录，不能当作不同账号隔离手段。

查看资源及服务日志：

```bash
free -h
df -h /var/lib/sorvflow
journalctl -u sorvflow -n 100 --no-pager
```

Nginx 的 HTTP 连接数限制或每秒请求限制，无法限制已经在后台继续运行的生成任务数；不要把它们当成生成队列。

## 若要让外部客户同时使用

应先增加登录身份到任务/文件的所有权校验、隔离日志、带持久化的任务队列、全站及每用户并发额度，并处理重启恢复。需要立即隔离的独立团队可采用相互独立的部署和存储，但本包的固定路径单实例模板不能原样运行多份。

## 这次检查如何验证

使用真实 HTTP 服务，给生成函数替换为不调用模型的模拟任务，同时提交 3 个不同项目。确认了各自 job/project ID 独立、停止信号只影响指定 job；同时复现了日志混入和客户端之间没有任务所有权校验。没有付费调用模型，也没有做真实生图吞吐测试，不能据此承诺支持多少人同时生图。

界面右上角“API 状态”的颜色表示当前服务和凭据配置：绿色为凭据已配置，黄色为未配置完整，演示色为服务未连接。悬停可看说明；健康检查不调用模型，因此绿色不代表模型 API 已成功连通。
