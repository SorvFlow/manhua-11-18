# 多账号与并发使用

应用已经实现独立账号。管理员开通/停用账号、重置初始密码；每个成员登录后仅访问自己的正文、漫画、日志和任务。管理员管理账号，但生成接口同样按当前账号隔离，不自动读取成员作品。现阶段按账号隔离，不含团队共享项目、共同编辑、付费充值或按调用金额结算。

## 已实现

- Argon2id 密码哈希、HttpOnly/SameSite 会话 Cookie、公网 HTTPS Secure Cookie、CSRF/Origin 校验；失败登录限频。
- 新建/重置账号首次登录需改密码；修改密码使全部旧会话失效。停用账号退出其会话、取消排队任务并请求停止运行任务。
- 项目与任务存 SQLite，文件在 `SORVFLOW_STATE_DIR/users/<用户UUID>/projects`；生成进程使用自己的数据/实验目录，日志按任务隔离。猜到其他人的项目或任务 ID 也返回 404。
- 同一账号同一项目的重复提交返回已有活动任务；正文或画风变化需新项目编号。
- 全局 FIFO 队列优先选择当前满足并发额度的最早任务；全局与每用户同时运行数、每用户排队数由数据库事务限制。
- 独立生成进程，浏览器关闭不停止任务；重启后运行任务重新排队，从已有管线检查点继续。旧进程的过期任务租约不能写入新结果。人工取消的任务不会被重启恢复。
- 停止运行任务采用协作取消，正在进行的模型请求可能完成后才停止，不代表供应商撤单或退费。
- 原有角色审核、连续性确认、重绘和方案对比按账号限定路径。方案对比推进使用同一个队列；实验数据需在对应账号的 `experiments` 目录中用原有 CLI 创建，网页仍没有创建实验向导。

## 起步配置

```dotenv
SORVFLOW_WORKERS=1
SORVFLOW_USER_RUNNING=1
SORVFLOW_USER_QUEUED=5
INKSTONE_IMAGE_CONCURRENCY=1
```

多个人可同时登录和提交；默认全站一次生成 1 个任务，其余排队。`WORKERS=2` 最多同时运行两个任务，`USER_RUNNING=1` 使每个人最多占一个。单个任务内的图片并发另由 `INKSTONE_IMAGE_CONCURRENCY` 控制。模型请求限频仍以生成进程为单位，尚未实现跨进程统一 RPM 或金额配额；提高 worker 数前先测供应商额度、服务器内存和费用。

一个部署只运行一个 Web 实例，调度器文件锁防止相同数据目录被重复启动；不要使用 uvicorn --workers、Gunicorn 多 worker 或多机共享此 SQLite 队列。更大规模需另外接集中式队列/数据库。

重启续跑依赖已有检查点，不能承诺外部 API 恰好调用一次：进程在供应商接受请求后异常退出时，恢复可能重新发起请求。任务 stderr 和作品会占用磁盘，需要按业务要求备份、归档或清理；目前没有自动保留期限。

## 数据与升级

账号、会话、任务在 `/var/lib/sorvflow/web/accounts.sqlite3`，用户文件在 `/var/lib/sorvflow/web/users`。模型密钥保留在服务环境文件，不下发给用户。

旧版 `/var/lib/sorvflow/comic_out` 不会删除或自动分配给新账号。先保留备份；确有需要时再设计带所有者确认的导入流程。当前没有旧项目一键导入功能。

## 验收

见 [TESTING.md](TESTING.md)：A/B 两个账号分别验证作品与任务隔离、排队、取消、停用与密码重置。自动化测试覆盖 HTTP 权限边界、并发重复提交、额度、调度锁、重启租约与实际服务端口选择；替换模型执行函数验收进程内部路径/日志隔离，未调用收费模型。真实生图效果和吞吐需在目标服务器另测。
